# 숏폼 광고 스튜디오

상품 URL 하나만 입력하면 상품 정보를 자동으로 분석해 9:16 세로형 15초 마케팅 영상(MP4, H.264)을 만들어주는 웹앱입니다.

## 실행 방법

### 1) 필수 프로그램 설치

- Node.js 20 이상
- **FFmpeg** (렌더링에 사용) — `ffmpeg`, `ffprobe` 실행 파일이 PATH에 있어야 합니다.
  ```bash
  sudo apt-get install -y ffmpeg
  ```
- **한글 폰트 (Noto Sans CJK)** — 영상 자막에 사용합니다.
  ```bash
  sudo apt-get install -y fonts-noto-cjk
  ```

### 2) 설치 및 실행

```bash
cd webapp
npm install
npm start        # http://localhost:3000
# 개발 중에는 npm run dev (파일 변경 시 자동 재시작)
```

## 환경변수

`.env.example`을 참고하세요. 전부 기본값이 있어 아무것도 설정하지 않아도 바로 동작합니다.

| 변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | 3000 | 서버 포트 |
| `FFMPEG_PATH` / `FFPROBE_PATH` | ffmpeg / ffprobe | 실행 파일 경로 (PATH에 없으면 절대경로 지정) |
| `MAX_RENDER_CONCURRENCY` | 2 | 동시에 렌더링할 수 있는 영상 수 |
| `MAX_ANALYZE_CONCURRENCY` | 4 | 동시에 분석할 수 있는 URL 수 |
| `MAX_ACTIVE_JOBS_PER_CLIENT` | 1 | 브라우저 1개당 동시 진행 가능한 작업 수 |
| `OUTPUT_EXPIRY_MINUTES` | 30 | 완성된 영상 다운로드 가능 시간 |
| `ANALYZE_TIMEOUT_MS` | 12000 | URL 분석 타임아웃 |
| `RENDER_TIMEOUT_MS` | 120000 | 영상 렌더링 타임아웃 |
| `MAX_RENDER_ATTEMPTS` | 2 | 렌더링 실패 시 자동 재시도 횟수 |
| `FONT_BOLD_PATH` / `FONT_REGULAR_PATH` | (자동 탐색) | 한글 폰트 파일 경로를 직접 지정하고 싶을 때 |
| `ALLOW_PRIVATE_HOSTS` | (미설정) | **로컬 개발/테스트 전용.** `1`로 설정하면 localhost·사설 IP 차단을 해제합니다. 운영 환경에서는 절대 설정하지 마세요. |

## 사용 흐름

1. 첫 화면에서 상품 URL을 입력하고 "영상 만들기"를 누르면 서버가 URL을 분석합니다 (JSON-LD → Open Graph → 메타데이터 → 본문 순으로 확인 가능한 정보만 사용, 없는 정보는 지어내지 않음).
2. 분석이 끝나면 목적 선택 카드(조회수 확보형 / 판매 전환형 / 브랜드 인지도형)가 나타납니다. 하나를 선택해야 "영상 제작 시작"이 활성화됩니다.
3. 제작이 시작되면 진행률과 현재 단계(대본 작성 중 → 렌더링 중)를 보여줍니다. 브라우저를 닫아도 서버에서 계속 진행되며, 다시 접속하면 자동으로 이어서 상태를 확인합니다(같은 브라우저에 저장된 작업 ID 기준).
4. 완성되면 9:16 플레이어로 미리보기하고 MP4를 다운로드할 수 있습니다.
5. 실패 시 입력했던 URL이 유지되며 "다시 시도"로 재시도할 수 있습니다.

## 아키텍처 개요

```
server/
  config.js              환경변수 기반 설정
  lib/
    ssrf.js              사설 IP·localhost 차단 (SSRF 방지)
    safeHttp.js          SSRF 방어 + 리디렉션 재검증 + 크기 제한이 적용된 저수준 HTTP 클라이언트
    fetchPage.js         상품 페이지 HTML 안전하게 가져오기 (타임아웃, 에러 한국어화)
    analyze.js           JSON-LD/OG/메타/SPA 임베디드 상태/본문 순으로 상품 정보 추출 (순수 함수)
    images.js            후보 이미지 다운로드 (실패한 이미지는 건너뜀)
    script.js            목적별 15초 타임라인/대본 생성 (HOOK→문제→장점→신뢰→CTA)
    render/
      fonts.js            한글 폰트 경로 탐색
      gradient.js          민트→화이트 그라데이션 배경(이미지 없을 때 대체용) 생성
      filterGraph.js        장면별 Ken Burns + 자막 + 전환 ffmpeg filter_complex 생성 (순수 함수)
      ffmpegRunner.js        ffmpeg/ffprobe 프로세스 실행 (타임아웃 포함)
      renderVideo.js          위 조각들을 조합해 최종 MP4 렌더링 + 검증(해상도/길이/코덱)
    jobStore.js           작업 상태 저장(메모리 + 디스크 영속화), 재접속 시 상태 복구, 만료 정리
    jobManager.js         작업 큐잉/재시도 오케스트레이션 (동시 실행 수 제한)
    queue.js              단순 동시성 제한 큐
  routes/api.js           REST API
  index.js                Express 서버 진입점
public/                   프런트엔드 (바닐라 HTML/CSS/JS, 빌드 도구 없음)
```

### 작업 상태 흐름

`queued → analyzing → awaiting_purpose(사용자가 목적 선택 대기) → queued → scripting → rendering → completed / failed`

`awaiting_purpose` 상태를 지나기 전에는 렌더링이 절대 시작되지 않습니다(목적 선택 전 영상 생성 방지).

### 안정성 관련 설계

- **SSRF 방지**: URL 형식 검증(http/https만 허용) + DNS 조회 결과까지 사설 IP 대역이면 차단 + 리디렉션마다 재검증 + DNS 리바인딩 방지(연결 시점 IP 재검증).
- **타임아웃**: URL 분석/이미지 다운로드/렌더링 각각 별도 타임아웃.
- **동시 실행 제한**: 분석/렌더링 큐 각각 동시 실행 수 제한, 브라우저(클라이언트)당 동시 작업 수 제한으로 중복 생성 방지.
- **부분 실패 허용**: 이미지 일부가 로딩 실패해도 나머지로 영상을 완성. 이미지가 하나도 없으면 그라데이션 배경으로 대체.
- **오류 격리**: 모든 라우트가 오류를 잡아 JSON으로 응답하며, 작업 큐의 오류도 해당 작업만 실패 처리할 뿐 서버 전체에 영향을 주지 않습니다.
- **재접속 지원**: 작업 상태를 디스크에도 저장해서, 서버 프로세스가 떠 있는 동안은 브라우저를 새로고침/재접속해도 진행 상태를 이어서 볼 수 있습니다.
- **정리**: 완료/실패한 작업의 임시 이미지·작업 폴더는 렌더링 직후 삭제되고, 다운로드는 만료 시간이 지나면 더 이상 제공되지 않습니다.

## 상품 정보 분석 체계

카테고리(디지털/가전, 건강기능식품)나 사이트별로 파싱 로직을 따로 두지 않고, 아래 우선순위를 모든 국내 쇼핑몰에 동일하게 적용합니다 (사이트마다 마크업이 달라도 이 순서대로 내려가면서 확인 가능한 값만 채웁니다).

1. **JSON-LD Product 스키마** (`<script type="application/ld+json">`) — 가장 신뢰도 높은 구조화 데이터.
2. **Open Graph 메타태그** (`og:title`, `og:image`, `product:price:amount` 등).
3. **일반 메타태그/제목** (`<title>`, `meta[name=description]`, 본문 이미지).
4. **SPA 임베디드 상태** — 신세계TV쇼핑처럼 상품 화면이 자바스크립트로 그려지는 사이트는 `window.__NEXT_DATA__` / `__INITIAL_STATE__` 같은 초기 상태 JSON에 상품명·가격·이미지가 들어있는 경우가 많아, 위 3단계에서 못 찾은 값만 여기서 보완합니다.
5. **본문 텍스트 휴리스틱** — 위에서도 못 찾은 가격·특징만 페이지 텍스트에서 정규식으로 추출.

앞 단계에서 이미 값을 찾았으면 뒷 단계는 건너뛰고, 끝까지 못 찾은 항목은 빈 값+경고로 남겨 내용을 지어내지 않습니다. (참고: 예시로 주신 두 URL은 이 세션의 네트워크 제한으로 직접 접속해 마크업을 확인하지는 못했고, 위 우선순위는 국내 쇼핑몰 일반 구조에 대한 설계입니다 — 실제 배포 서버에서 두 링크로 테스트해보고 특정 필드가 안 채워지면 알려주시면 해당 사이트 전용 보완 규칙을 추가하겠습니다.)

## 테스트한 내용

- 정상 상품 페이지(JSON-LD 포함) → 분석 → 3가지 목적 각각으로 렌더링 → 다운로드까지 전체 플로우 (curl 및 Playwright로 실제 Chromium 브라우저에서 클릭 흐름 확인, 모바일/PC 뷰포트 모두 확인)
- 정보가 거의 없는 페이지(이미지·가격 없음) → 경고만 표시하고 지어내지 않음 → 그라데이션 배경으로 영상 완성
- 잘못된 URL 형식, 존재하지 않는 프로토콜(ftp), 연결 거부(ECONNREFUSED) → 친절한 한국어 오류 메시지
- localhost/사설 IP/클라우드 메타데이터 주소(169.254.169.254) 접근 차단 확인 (기본 설정 상태에서)
- 응답이 느린 URL → `ANALYZE_TIMEOUT_MS` 경과 후 타임아웃 실패 처리, 서버는 계속 정상 동작
- 같은 브라우저에서 작업 진행 중 중복 요청 시 429 응답
- 렌더링 결과물이 정확히 1080×1920, H.264, 약 15.0초인지 ffprobe로 검증
- 세 가지 목적별로 HOOK/CTA 문구가 실제로 달라지는지 확인

### 알아둘 점 (테스트 환경 한계)

자동 브라우저 테스트에 사용한 Playwright 번들 Chromium은 라이선스 문제로 **H.264 디코더가 빠진 오픈소스 빌드**라서 `<video>` 재생 자체는 이 샌드박스에서 직접 확인하지 못했습니다(`canPlayType('video/mp4; codecs="avc1..."')`가 빈 문자열 반환, 반면 VP9는 정상 재생됨). 실제 크롬/사파리/엣지/모바일 브라우저는 모두 H.264를 지원하므로 정상 재생됩니다. 파일 자체의 정확성(해상도, 코덱, 길이, Range 요청 스트리밍)은 ffprobe와 curl로 별도 검증했습니다.

## 알려진 제한 (MVP 범위)

- 렌더링 진행률은 실제 ffmpeg 진행률이 아니라 단계 기반 추정치입니다(먼저 동작하는 MVP 우선 원칙에 따름).
- 서버 재시작 시 진행 중이던 작업은 실패로 표시됩니다(재시도 가능). 완료된 작업 기록은 유지됩니다.
- 자막/카피는 실제 추출된 데이터를 기반으로 한 템플릿 방식이며, 외부 LLM API를 사용하지 않습니다(추가 API 키 불필요).
